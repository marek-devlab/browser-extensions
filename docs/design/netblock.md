# UX/UI-дизайн: Request Blocker (`extensions/netblock`)

> **Версия 1.1** (2026-09-15; v1.1 — после спайков [`e2e/netblock-spikes/REPORT.md`](../../e2e/netblock-spikes/REPORT.md)). Дизайн-документ расширения №16. Исследование, на котором он стоит, — [`docs/research/2026-09-15-netblock.md`](../research/2026-09-15-netblock.md) (далее — «Research»); факты платформы здесь не пересказываются, а ссылаются на его параграфы.
> Цель одной фразой (не обсуждается): **«Блокировать и фейлить сетевые запросы по правилам — для тестирования отказоустойчивости фронтенда»**.
>
> ⚠️ — места, где «очевидное» решение ломается о платформу, политику стора или честность UI.
> 🔴 — запрет.
>
> Конвенции дома — [`PLAN.md`](../../PLAN.md) §18a–18d: не врать в UI, `data-theme` + `color-scheme`, severity не только цветом, `aria-live` на асинхронщине, `local` вместо `sync` для больших данных, Web Lock вокруг RMW.
>
> Код в `extensions/netblock/` этим документом **не пишется**. Это спецификация.

## 0. Итог одним экраном

| Решение | Значение |
|---|---|
| **Аудитория** | Разработчики и QA. Не «блокировщик рекламы для всех» — это `adblock`, и смешивать их 🔴 нельзя (§1.1) |
| **Действия v1** | `block` · `fail` (с типом сетевой ошибки) · `delay` · `status` (вернуть заданный код, опционально с телом). 🔴 **Не** redirect, не modify headers, не mock «настоящих» ответов — это дрейф к Requestly/ModHeader и другая цель (§11) |
| **Условия v1** | URL (contains / equals / wildcard / regex), метод, тип ресурса, домен страницы, **код ответа**, заголовки ответа |
| **Состояние v1** | `once` · `times: N` · `nth: N` (+ «каждый N-й») · `skipFirst` · `window` (после события, на N с) · `afterRule` («B после A») · `probability` (с seed). `scenario` (state machine) — 🔜 v2. В Chrome `afterRule`/`window`/`skipFirst` исполняются реактивно в DNR (спайк S3: последовательные — 40/40, параллельные — 0/5), точные `nth`/`once`/`times` — в `page`/`dbg` |
| **Движки (Chrome)** | `dnr` → `page` → `debugger`, выбор `auto` по правилу (Research §4). У каждого правила бейдж движка, у каждого движка — честная подпись ограничения (§6) |
| **Движок (Firefox)** | один — blocking `webRequest`. Покрывает все условия и все состояния без гонок; `status` с телом деградирует до `cancel` + честный бейдж (Research §2.6) |
| **Поверхности** | popup 360px (эта вкладка) · **tool page** во вкладке (Правила · Лог · Настройки) · `options_ui` → та же tool page `#/settings`. DevTools-панель и side panel — 🔜 v2 (§1.4) |
| **Разрешения Chrome (install)** | `storage`, `alarms`, `scripting`, `webRequest`, `declarativeNetRequest` → **одно** предупреждение «Block content on any page you visit» (неизбежно для block без host-доступа) |
| **Разрешения Chrome (optional)** | `optional_host_permissions: <all_urls>` — по кнопке «Включить на этом сайте»; `optional_permissions: ['debugger']` — по кнопке «Network-level mode» на вкладке |
| **Разрешения Firefox** | `storage`, `alarms`, `webRequest`, `webRequestBlocking`, `<all_urls>` (install-time — как у `adblock`, без host access `cancel` — no-op) |
| **Сеть** | **ноль**. CSP без `connect-src`. Никаких списков правил «с сервера», delay-серверов, телеметрии (урок ModHeader 07.2026 — Research §3) |
| **Персист** | `local:rules` (≤ 2 МБ) · `sync:prefs` (≤ 2 КБ) · `session:state` (счётчики) · `session:log` (кольцевой буфер, RAM+session) · `perm` — состояние выводится из `permissions.contains()` |
| **Мобильный** | Firefox for Android — работает (webRequest blocking есть); без `debugger`, без `contextMenus`, popup = пункт меню, tool page во вкладке (Research §2.6) |

## 1. Информационная архитектура

### 1.1 Правило, из которого выводится всё остальное

Есть два соседних продукта, в которые это расширение легко «стечь», и оба — нарушение single purpose:

- **`adblock`** — «блокировать рекламу и трекеры». Общий глагол «блокировать», но другая аудитория, другие условия (списки, косметика), другие обещания. Ревьюер, увидев в Request Blocker вкладку «EasyList», напишет Red Argon.
- **Requestly/ModHeader-класс** — «изменять запросы» (redirect, headers, mock bodies). Это *инструмент разработки*, а не *инструмент тестирования отказов*.

> 🔴 **Каждое действие в v1 отвечает на один вопрос: «что видит фронтенд, когда сеть ломается?»** Заблокировано · упало с ошибкой · долго · вернуло 503. Всё, что «делает запрос успешнее или другим» (redirect, подмена тела на «хороший», headers), — не сюда.

Следствия: нет импорта фильтр-листов; нет «Map Local»; `status` с телом — только для *кодов ошибки* (≥ 400) в UI по умолчанию; для 2xx — доступно, но с подписью «это уже мок, а не отказ» (§6).

### 1.2 Поверхности и зачем каждая

| Поверхность | Файл | Зачем именно она | Почему нельзя без неё |
|---|---|---|---|
| **Popup** | `entrypoints/popup/` | Контекст **этой вкладки**: доступ к сайту (Chrome), активные правила здесь, счётчики, тумблер Network-level mode (Chrome), «Открыть инструмент». 5 секунд жизни | Клик по иконке — единственный жест, дающий `activeTab` и `permissions.request()` из user gesture. Без popup нет «включить на этом сайте» |
| **Tool page** (главная) | `entrypoints/tool/` → `tool.html` | Редактор правил (форма, не текст), собственный сетевой лог с «создать правило из строки», настройки | Правило — это 4 секции × ~15 полей. В 360px это не редактор. Лог — таблица на сотни строк. Живёт минутами, переживает потерю фокуса |
| **Options** | `options_ui.page = "tool.html#/settings"`, `open_in_tab: true` | Пункт «Параметры» браузера ведёт в **тот же** инструмент | Отдельная options-страница = вторая точка входа = дрейф к bundle'у (та же логика, что в `devdata` §1.2) |

**Почему не DevTools-панель в v1** (хотя Netify/Requestly/Mokku живут именно там):
1. ✅ Спайк S1/S1c (Chromium 153): `debugger.attach` и открытые DevTools на одной вкладке **сосуществуют** в обоих порядках, `onDetach` не приходит — справочник устарел относительно кода. Этот пункт больше не блокер.
2. Firefox for Android — `devtools` API нет вообще.
3. Панель существует, только пока DevTools открыт, — ровно тот недостаток Chrome «Request conditions», который мы закрываем.

🔜 v2: DevTools-панель как **третья проекция того же React-приложения** (тот же store), с логом из `devtools.network`. Не проверено: одновременная работа DevTools «Request conditions» и нашего `Fetch.enable` — ручной прогон перед v2.

### 1.3 Навигация внутри tool page

```
Правила      ← список + редактор (split view). Группы, toggle, порядок = приоритет
Лог          ← собственный сетевой лог этой сессии; «создать правило из строки»
Настройки    ← тема, язык, лимиты лога, экспорт/импорт, сброс
```

Хэш-роутер: `#/rules`, `#/rules/:id`, `#/log`, `#/settings`. Popup → «Открыть инструмент» открывает `#/rules?tab=<tabId>` (фильтр лога по вкладке).

### 1.4 Чего нет и почему

| Нет | Почему |
|---|---|
| DevTools-панель, side panel | §1.2; 🔜 v2 |
| Контекстное меню «Заблокировать этот ресурс» | Нет на Android; для dev-аудитории «создать правило из лога» точнее. 🔜 v2 desktop-only |
| Текстовый синтаксис правил (ABP/uBO/mitmproxy-фильтры) | Высокий порог входа; форма честнее показывает, какой движок выбран. Импорт `~c 500 & ~u /api` — 🔜 v2 как *формат импорта* |
| Пользовательский JS-предикат | Chrome — только через `userScripts` с тумблером 138+; Firefox — 🔴 запрещён политикой AMO для не-менеджеров (Research §5). Не в v1 |
| Аккаунт, синхронизация через облако, «поделиться правилами ссылкой» | Сеть = ноль. Экспорт JSON-файлом |

Firefox: та же карточка с текстом «В Firefox тип сетевой ошибки выбрать нельзя — запрос будет отменён (как «Блокировать»)» и правило **активно** в деградированном виде, бейдж `wr↓`. То же для «Код ответа» — спайк S2: Firefox умеет подменить только *тело* (со статусом 200), не код.

### 2.9 Узкий экран / мобильный (< 720px)

Split view → один столбец: список правил, тап → редактор на весь экран с кнопкой «← Правила». Лог — карточки вместо таблицы (время · метод · URL · статус · правило). Firefox for Android: нет NL-блока, нет HAR-экспорта в popup (popup — пункт меню, ведёт в tool page).

## 4. Потоки

### 4.1 Первое правило: «сломать checkout на третьем вызове»

1. Popup → «Включить на shop.example.com» → браузерный промпт → `permissions.contains` = true → регистрируем page-движок на origin, включаем `webRequest`-наблюдение.
2. «Открыть инструмент» → `#/log?tab=412`. Пользователь кликает checkout на сайте, в логе появляется `POST /api/checkout 200`.
3. ⋯ на строке → «Создать правило из запроса» → редактор с предзаполненными URL (`equals`, полный путь без query), методом `POST`, типом `xhr/fetch`, доменом страницы.
4. Состояние → «N-й: 3». Бейдж движка: `dnr` → **`page`** с подписью «N-й запрос считается точно только на клиенте; DevTools покажет реальный ответ».
5. Действие → «Код ответа 503». Сохранить.
6. На сайте: 1-й, 2-й checkout — 200; 3-й — приложение получает 503. Popup: `2/3 ↻` → `3/3`, лог: `503 ✱ Checkout…`.

**Ошибки/ветки:** доступ не выдан → шаг 4 показывает «page-движок недоступен без доступа к сайту — правило будет неактивно» с кнопкой «Включить»; пользователь выбрал «все типы ресурсов» → бейдж `dbg` + карточка §2.8.

### 4.2 «Картинки с CDN не грузятся» (stateless block)

1. `+ Правило` → URL `wildcard` `*cdn.example.com/*`, тип `image`, действие «Блокировать». Бейдж **`dnr`** — «работает даже без доступа к сайту; счётчик приблизительный».
2. Сохранить → `updateDynamicRules` (все вкладки) или `updateSessionRules` с `tabIds` (активная).
3. Счётчик: `onErrorOccurred` с `net::ERR_BLOCKED_BY_CLIENT` на URL, совпадающем с нашим матчером, → `≈N` (Research §2.1: чьё правило — неизвестно). На сайтах без доступа счётчика **нет** — показываем «—», не «0».

### 4.3 «Реальная 500 → показать пользователю оффлайн-экран» (по коду ответа)

1. Условие «Ответ: код `5xx`», действие «Ошибка сети: InternetDisconnected». Бейдж **`dbg`** (Chrome) / **`wr`** (Firefox: `cancel` — «тип ошибки имитируется отменой»).
2. Chrome: правило неактивно, пока на вкладке не включён NL. Popup → NL → `<dialog>` §2.7 → attach → `Fetch.enable([{urlPattern, requestStage:'Response'}])`.
3. `Fetch.requestPaused` с `responseStatusCode: 500` → `Fetch.failRequest({errorReason:'InternetDisconnected'})`. Лог: `500 → failed(InternetDisconnected)`.
4. Пользователь закрыл вкладку → `tabs.onRemoved` → detach → баннер исчезает через 5 с.

**Ветки:** `onDetach(canceled_by_user)` → toast в tool page/popup «Network-level mode выключен кнопкой «Отмена» в баннере; правила `dbg` неактивны» + деградация: остальные движки продолжают. DevTools открыт при attach → если attach падает — карточка «Закройте DevTools на этой вкладке и попробуйте снова» (текст из `perf/utils/debugger-bytes.ts`).

### 4.4 «Флаки-сеть»: 30% запросов к API — таймаут

1. Условие URL `contains` `/api/`, состояние «Вероятность 30%, seed 42», действие «Задержка 10 000 мс» или «Ошибка сети TimedOut». Бейдж `page` (delay) или `dbg` (TimedOut).
2. Seed → воспроизводимо: одна и та же последовательность решений при одном seed и одном порядке запросов. В UI: «Тот же seed — та же последовательность отказов».

### 4.5 Импорт правил

1. Настройки → Импорт → файл JSON → валидация (§7.1) → предпросмотр «N правил, M с ошибками» → таблица ошибок с номерами → «Импортировать валидные» / «Отмена».
2. Regex проверяются `declarativeNetRequest.isRegexSupported` (Chrome) и safe-regex-эвристикой + таймаутом компиляции (обе платформы) — как гвард ReDoS в `blur`.

## 5. Состояния

### 5.1 Empty (нет правил)

Tool page: иллюстрация-схема «URL → условие → действие», три пресета одной кнопкой: «Заблокировать всё с домена…», «Каждый 3-й запрос к … → 503», «30% запросов к … → таймаут». Пресет открывает редактор, **не** создаёт правило молча.

### 5.2 Loading — компиляция правил

Сохранение правила → `updateSessionRules/updateDynamicRules` + перерегистрация page-скрипта + `Fetch.enable` с новыми паттернами. Индикатор на кнопке «Сохранить», `aria-live="polite"` «Правило применено». ⚠️ До завершения компиляции правило показывается как «применяется…», не «включено» — DNR-update асинхронен.

### 5.3 Degraded — Chrome без доступа к сайту

Popup §2.1. В списке правил: `dnr`-правила — активны; `page`/`dbg` — серые с причиной. Лог для этой вкладки — пустой с подписью «Нет доступа к сайту — лог недоступен», не «0 запросов».

### 5.4 Degraded — Firefox: действие не поддерживается полностью

`fail(reason)` → `cancel` (`wr↓` «отменён, тип не имитируется»). `status` → ✅ спайк S2 (Firefox 155): `redirectUrl` на `data:`/`moz-extension://` из `onHeadersReceived` **доходит** до `fetch` и XHR, same- и cross-origin, но страница видит **`status: 200`** — код ответа в Firefox изменить нельзя (в `BlockingResponse` нет поля). Решение v1: `status` в Firefox = `cancel` + бейдж `wr↓` «Firefox не позволяет изменить код ответа; запрос отменён». Подмена тела с кодом 200 — 🔜 v2 как отдельное действие `mockBody`, если понадобится. `delay` — штатно: async blocking-листенер (S2: 300 мс → ≈325 мс).

### 5.5 Degraded — NL-режим отключился

Причины: `canceled_by_user`, `target_closed`, enterprise-политика («Host access is restricted by policy»). Открытие DevTools **не** детачит (спайк S1/S1c, Chromium 153) — но обработчик общий, поэтому если будущий Chrome начнёт детачить, UI уже готов. Toast с причиной **словами браузера** + кнопка «Включить снова». Правила `dbg` → неактивны, остальные работают. ⚠️ Paused-запросы: `detach` в `finally` любой ошибки обработчика; watchdog-`alarm` раз в 30 с проверяет, что для каждой attached-вкладки нет запросов, ждущих > 20 с, иначе `continueRequest` всем и лог «сброшены зависшие запросы».

### 5.6 Degraded — счётчики после перезапуска

Перезапуск браузера → `storage.session` пуст → все `nth/times/once` начинаются заново. В попапе одноразовый бейдж «Счётчики сброшены после перезапуска браузера». Это не ошибка — это документированное поведение, и мы его называем.

### 5.7 Error — правило не скомпилировалось

`updateSessionRules` reject (лимит 5 000, невалидный regex, > 2 КБ regex) → правило помечается ⚠ с текстом ошибки браузера дословно + наш перевод («Регулярное выражение слишком сложное для Chrome (RE2, ≤ 2 КБ). Упростите или используйте `contains`»). 🔴 Не выключаем правило молча.

### 5.8 Лимиты

| Лимит | Значение | Поведение |
|---|---|---|
| Правил всего | 500 | Мягкий кап: предупреждение «Chrome: 5 000 session-правил на все вкладки, у каждого правила по правилу на вкладку»; hard-кап 2 000 |
| Regex-правил | 200 | Chrome: 1 000 на тип; оставляем запас `adblock`? — нет, `adblock` regex не использует; Firefox: 1 000 |
| Тело ответа | 64 КБ | Больше — отказ с сообщением |
| Лог | 500 / 2000 / 5000 записей, ≤ 4 МБ `session` | Кольцевой буфер, старое вытесняется, счётчик «вытеснено N» |

## 6. Честность UI — где обязаны признать ограничение

1. **DNR-счётчики приблизительные (`≈`).** `ERR_BLOCKED_BY_CLIENT` не говорит, чьё правило; `getMatchedRules` квотирован и требует `activeTab`. Подпись в логе и попапе (Research §2.1).
2. **page-движок ≠ сеть.** DevTools Network покажет реальный ответ; приложение — подменённый. Значок `✱` на каждой такой строке лога + подпись у бейджа `page`. Не ловит картинки/скрипты/воркеры — при выборе таких типов бейдж переключается на `dbg` и говорит почему.
3. **`responseHeaders` в DNR — «полублок».** Сервер запрос получил; страница — нет. Подпись у секции «Заголовок ответа»: «Сервер уже обработал запрос; блокируется доставка ответа». Только Chrome ≥ 128 (feature-detect через `RuleConditionKeys`, иначе секция disabled с причиной).
4. **NL-режим показывает баннер во всех окнах** и может выключиться по «Отмена» или DevTools. Сказано до включения (§2.7) и в момент выключения (§5.5).
5. **NL-режим замедляет вкладку.** «Перехват на уровне сети добавляет задержку каждому запросу; для загрузок больших файлов — заметно» (Research §2.3: до 17–21× на аплоадах). Подпись в блоке NL.
6. **Firefox: тип сетевой ошибки не выбирается, статус не подменяется** — только отмена. Бейдж `wr↓` + текст.
7. **Счётчики сбрасываются при перезапуске браузера** (§5.6).
8. **Реактивные правила ловят только последовательные запросы.** Спайк S3: `updateSessionRules` — 0.2–0.7 мс, последовательный B после A блокируется 40/40 даже без паузы, **параллельные A ∥ B — 0/5**. Подпись у реактивных L1-правил: «≈ запросы, ушедшие параллельно с триггером, могут проскочить».
9. **Без доступа к сайту лога нет** — «—», не «0».
10. **Правила = данные.** В Настройках и листинге: «Расширение не исполняет пользовательский код; правила — это конфигурация».
11. **Вероятность с seed воспроизводима только при том же порядке запросов.** Подпись у seed.
12. **`status` 2xx — это мок, а не отказ.** При вводе кода < 400 — подсказка «Это уже подмена успешного ответа. Инструмент предназначен для отказов; для моков API есть специализированные инструменты» — не блокируем, но говорим.

## 7. Безопасность

### 7.1 Импорт правил — недоверенный ввод

- JSON-схема с `additionalProperties: false`; неизвестные поля — ошибка, не игнор.
- `__proto__`/`constructor` ключи → отказ (урок `devdata` §-хардненинга).
- Regex: `isRegexSupported` (Chrome), safe-regex-эвристика (звёздная высота, вложенные квантификаторы), компиляция с таймаутом в Worker (Firefox — JS `RegExp`, ReDoS реален и бьёт по **каждому** запросу в blocking-листенере). ⚠️ Гвард и на build-time матчера «Проверить URL» — он тоже исполняет regex.
- `body` ≤ 64 КБ, content-type из allowlist (`application/json`, `text/plain`, `text/html`, `application/xml`); 🔴 `text/html` с телом отдаём только со статусом ≥ 400 и `X-Content-Type-Options: nosniff` — иначе мы инструмент для инъекции HTML в чужой origin.
- Размер файла импорта ≤ 2 МБ.

### 7.2 Что не персистится никогда

- 🔴 **Лог на диск** (`local`) — URL и заголовки страниц = browsing activity. Только `session` + RAM.
- 🔴 Заголовки запросов с `Authorization`/`Cookie` в логе — маскируются всегда (`•••`), без опции.
- Тела ответов страниц — не читаем вообще (`Fetch.getResponseBody` не вызывается; условие по телу ответа — 🔜 v2 с отдельным согласием).

### 7.3 Инъекция page-движка

- MAIN-world скрипт — **статический файл из бандла**, никакого `eval`/`new Function`; правила приходят через `postMessage` от ISOLATED-релея с проверкой `event.source === window` и nonce, сгенерированного `crypto.getRandomValues` (как в `perf` MAIN/relay).
- Патч `fetch`/XHR хранит оригиналы в closure; `toString` не подделываем (обнаружимость честно в описании).
- Регистрируется только на выданных origin (`registerContentScripts` с `matches` из `permissions.getAll().origins`), снимается на `permissions.onRemoved`.

### 7.4 Действия с заголовками — 🔴 нет в v1

Единственный header, который мы трогаем, — `X-Content-Type-Options` на собственном `status`-ответе. Никакого `modifyHeaders` → нет риска ослабить CSP (AMO-политика, Research §2.6).

### 7.5 Сеть

Ноль. CSP расширения без `connect-src`. `status`-тела, delay, всё — локально. Guards (`scripts/check-guards.mjs`) дополнить: в манифесте нет `declarativeNetRequestFeedback`; `debugger` только в `optional_permissions`; нет `connect-src` в CSP.

| Правило с `tabIds` пережило вкладку (SW спал) | На старте: `getSessionRules()` ∖ живые вкладки → `removeRuleIds` |
| Два одновременных `onCompleted` инкрементируют один счётчик | `navigator.locks.request('netblock-state')` вокруг RMW — единственный писатель |
| Page-скрипт инжектнулся после первого запроса страницы | `document_start` гарантирует до кода страницы; запросы из `<link rel=preload>`/HTML-парсера — не наши (честность §6.2) |
| Firefox: blocking-листенер ждёт `storage.session` > N мс | Все запросы вкладки ждут. Кэш состояния в памяти event page; чтение storage — только при холодном старте; таймаут 200 мс → пропустить запрос (fail-open) + лог |
| Импорт битого файла | §7.1: ничего не применяется частично без явного «импортировать валидные» |
| Enterprise-политика запрещает attach | Ошибка браузера дословно + «NL недоступен на этом устройстве», `dbg`-правила неактивны |

Принцип: **fail-open**. Если движок сломался — запросы проходят, а не висят. Инструмент тестирования, который сам стал причиной отказа, — худший исход.

## 9. Доступность и тема

### 9.1 Тема — конвенция дома
`data-theme` + `color-scheme` на `<html>`, токены `@blur/ui`, антифликер-сид из `localStorage` (как `seo/utils/theme.tsx`).

### 9.2 Не только цветом
Бейджи движков — текст (`dnr`/`page`/`dbg`/`wr`) + иконка, не цвет. Статусы в логе — число/слово + значок (`✱`, `≈`, `○`). Неактивное правило — `○` + курсив + текст причины, не только серый.

### 9.3 Клавиатура
Список правил — `role="listbox"`, `↑↓` навигация, `Space` toggle, `Alt+↑↓` — порядок (drag имеет клавиатурный эквивалент). Редактор — обычная форма, `Ctrl/⌘+S` сохранить. Лог — `role="grid"`, `Enter` на строке → меню действий. `aria-live="polite"` для «Правило применено», `assertive` — для «NL-режим выключен».

## 10. Современная платформа (2026)

### 10.1 Берём
- `declarativeNetRequest` session-правила с `tabIds` (Chrome 92+), `responseHeaders` (128+) под feature-detect `RuleConditionKeys` (145+); `isRegexSupported` для валидации.
- `scripting.registerContentScripts({world:'MAIN'})` (Chrome 111+, Firefox 128+ — ⚠️ проверить в WXT-сборке Firefox MV2; там page-движок не нужен, отключаем).
- CDP `Fetch` (Request+Response stage), `Target.setAutoAttach` для воркеров — 🔜 v2, v1 только фреймы вкладки. ⚠️ Спайк S4: `Fetch` **не видит WebSocket-хендшейк** → в `dbg` тип `websocket` недоступен; WebSocket блокируется только DNR (`block`), UI при `websocket` + `fail/delay/status` говорит об этом.
- `chrome.storage.session` (Chrome 112+, Firefox 115+), `navigator.locks` (SW и event page).
- `URLPattern` для op `urlpattern` — 🔜 v2 (⚠️ поддержка в Firefox — проверить, в v1 op не предлагаем).
- `setExtensionActionOptions({displayActionCountAsBadgeText})` — нет: наш бейдж — «≈» и по всем движкам, свой через `action.setBadgeText`.

### 10.2 Не берём
- `webRequestBlocking` в Chrome (policy-only), `declarativeNetRequestFeedback`, `userScripts`, `proxy`, `webNavigation` (сброс по навигации — через `onBeforeRequest(main_frame)`), `tabs` (host из `activeTab` + `permissions`).
- `@adguard/tsurlfilter` — не наш синтаксис.

### 10.3 Библиотеки — итог
React 19 + `@wxt-dev/module-react`, `@blur/ui`, `@webext-core/messaging`; своя `wildcard→regex` конвертация (20 строк); `mulberry32` для seed (10 строк); валидация импорта — `valibot` (≈ 6 КБ) или ручная; HAR-экспорт — свой сериализатор (без тел). Ничего тяжёлого.

### 10.4 Общий код
- `extensions/adblock/utils/backends/{types,dnr,webrequest,webrequest-match}.ts` → кандидат на `@blur/netcore` (интерфейс `BlockingBackend`, матчер `urlFilter`-семантики) — ⚠️ техдолг: сначала вынести, потом импортировать, а не копировать третий раз (`PLAN.md` §18 урок про `packages/ui`).
- `extensions/perf/utils/debugger-bytes.ts` → attach/detach-обвязка и тексты ошибок → в тот же пакет.
- Web Lock RMW-helper из `blur`.

## 12. Найденные противоречия и недоспецифицированное

1. ✅ **Реактивный DNR — решено спайком S3.** `updateSessionRules` 0.2–0.7 мс; последовательные зависимости ловятся 40/40, параллельные — 0/5. v1: **L1 реактивно исполняет `afterRule`, `window`, `skipFirst→thenFail`** (с подписью «≈ параллельные могут проскочить»); точные `nth`/`once`/`times` — только `page`/`dbg`/`wr` (снять правило ровно после одного срабатывания DNR не может без гонки на параллельных копиях). Замер — тёплый SW; холодный старт добавляет неизмеренную задержку → правило «после события» ставится заранее, если триггер — не сетевое событие (клик).
2. ✅ **`status` в Firefox — решено спайком S2.** `redirectUrl` → `data:` доходит, но статус всегда 200 → `status` в Firefox = `cancel` + `wr↓` (§5.4).
3. ✅ **`debugger` + DevTools — решено спайком S1/S1c.** Сосуществуют в обоих порядках на Chromium 153; §1.2/§2.7/§5.5 обновлены. Остаётся ручной прогон с DevTools «Request conditions» перед v2-панелью.
4. ⚠️ **WXT и `optional_permissions: ['debugger']` в Firefox MV2-сборке** — ключ должен исчезнуть из Firefox-манифеста (там нет `debugger`); в `perf` это уже решено — переиспользовать, но проверить `npm run guards` на новом манифесте.
5. ⚠️ **`@blur/netcore` не существует.** §10.4 требует вынести бэкенды из `adblock` **до** старта — иначе третья копия матчера. Блокер старта, не блокер дизайна.
6. **Нумерация.** Это №16 при отложенном №15 (`proof`); в `PLAN.md` нужна Часть IV или явная ссылка на Research — иначе «карта» расширений в `README.md` (14 + proof) врёт.
