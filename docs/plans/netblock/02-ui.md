## 2. Роутер и данные

- Хэш-роутер (§1.3): `#/rules`, `#/rules/:id`, `#/rules/new`, `#/log`, `#/settings`; `?tab=<id>` — фильтр лога и «только активная вкладка» в редакторе. `options_ui` → `#/settings` (манифест уже).
- Данные — ТОЛЬКО через `utils/protocol.ts`. Хуки с одним писателем (конвенция дома, `usePrefs`):
  - `useRulesStore()` — `listRules` при монтировании, push `rules:applied` обновляет `applied`; операции `saveRule/deleteRule/reorderRules/saveGroup/deleteGroup/deleteAllRules` возвращают `applied` → до ответа правило показано как «применяется…» (§5.2).
  - `useCaps()` — новый запрос `getCaps` → `{ platform, caps }`; для live-бейджа `caps.page &&= prefs.pageEngineEnabled`.
  - `useLogFeed(tabId)` — push `log:append` + поллинг `getLogPage` с курсором `afterId` раз в 1 с, пока `document.visibilityState === 'visible'`; дедупликация по `id`; «пауза» останавливает поллинг и складывает пуши в буфер.
  - `useTabSummary()` в popup — `getTabSummary` раз в 1 с (счётчики живые).
- Новые протокольные сообщения (аддитивно): `getCaps` → `{ platform, caps }`; `testUrl` получает опциональные `resourceType`, `pageDomain` (обработчик — мой).
- Бейдж движка пересчитывается **на каждое изменение формы** через `selectEngine(draft, platform, caps)` (§2.4) — та же функция, что в background, поэтому popup/tool/фон не расходятся.

## 4. A11y (§9)

- Список правил: `role="listbox"` + `role="option"` (`aria-selected`), `↑↓`/Home/End — фокус, `Space` — toggle enabled, `Enter` — открыть, `Alt+↑/↓` — переставить (клавиатурный эквивалент drag), `aria-describedby` — причина неактивности. Roving `tabIndex`.
- Редактор: обычная форма, `Ctrl/⌘+S` = Сохранить; ошибки полей — `aria-invalid` + `aria-describedby`; `<output aria-live="polite">` «Правило применено».
- Лог: `role="grid"` + `row`/`columnheader`/`gridcell`; `↑↓` строки, `Enter`/`ContextMenu` — меню действий строки; `aria-live="polite"` для счётчика записей — нет (шум), только для «лог очищен».
- Toast NL: `role="alert"` (`aria-live="assertive"`). Бейджи — текст + глиф (`dnr` ▸, `page` ✱, `dbg` ⚡, `wr` ▹), неактивно — `○` + курсив + текст.
- Тема: `data-theme` + `color-scheme` из `@blur/ui`; антифликер `seedTheme` (уже в `main.tsx`), локаль — `seedLocale` в `main.tsx` + `LocaleProvider`.

## 5. i18n

- EN — источник, RU — полное зеркало, **ET — настоящий перевод** (не копия EN), всё в `utils/i18n.ts`, ключи фазы 1 сохранены. Не переводятся (правило фазы 1): бейджи, HTTP-методы/коды, CDP-причины, имена API, глифы.
- Переключатель — `LanguageSwitcher` из `@blur/ui` (сегмент EN/RU/ET; спека просит select «Авто·EN·RU·ET» — дом по умолчанию EN независимо от браузера, «Авто» нет — отклонение, как во всех расширениях волн 1–3).

## 6. Тесты

`e2e/netblock/ui.spec.ts` + `playwright.config.ts` (по образцу `e2e/seo`): persistent Chromium с `.output/chrome-mv3`; `tool.html` и `popup.html` по `chrome-extension://<id>/`. 10 проверок: пустое состояние + пресет открывает редактор; создание правила → в списке с бейджем `dnr` (block + wildcard + image) и `page` (nth + status на xhr); бейдж меняется на лету при вводе кода ответа; импорт битого JSON → таблица ошибок, импортируются только валидные; настройки сохраняются после перезагрузки; лог рендерит строки из посеянного `session:log`; ноль ошибок консоли; `Alt+↓` меняет порядок; RU/ET меняют видимые строки. Скрипт `e2e:netblock-ui`; в цепочку `e2e` — добавляется (там уже есть `e2e:seo`).

## 7. Риски и открытые вопросы

- `caps.page` в background не читает `prefs.pageEngineEnabled` — UI учитывает pref для live-бейджа; фон должен сделать то же при интеграции (иначе бейдж и факт разойдутся).
- `log:append` — push одной записи; при спящем SW и закрытой странице пуши теряются → поэтому поллинг с курсором, а не только push.
- `debugger` в Chrome-сборке отсутствует (решение фазы 1) → NL-блок popup, тумблер «помнить NL» и статус NL в Settings отрисовываются только при `networkLevelAvailable/debuggerAvailable === true`; код §2.3/§2.7 живёт, но скрыт. В Settings при недоступности — честная строка `puNlUnavailable`.
- Drag-reorder через HTML5 DnD: в Firefox for Android drag недоступен, клавиатуры обычно нет — перестановка на мобильном в v1 не реализована (открытый вопрос: кнопки «↑/↓» в строке).
- «Домен страницы» в «создать правило из запроса» недоступен: `LogEntry` не несёт initiator — предзаполняются URL (equals, без query), метод, тип.
- Перевод ошибок браузера (§5.7) — эвристика по подстрокам (`regex`, `rule limit`, `MAX_NUMBER_OF`); незнакомые — только дословно.
